# Universo Platformo: Сравнение архитектуры React и Godot

**Версия документа**: 1.0.0  
**Дата**: 2025-11-17  
**Репозиторий React**: [teknokomo/universo-platformo-react](https://github.com/teknokomo/universo-platformo-react) (v0.38.0-alpha)  
**Репозиторий Godot**: [teknokomo/universo-platformo-godot](https://github.com/teknokomo/universo-platformo-godot) (v0.1.0-dev)

## Краткое резюме

Этот документ предоставляет всеобъемлющее сравнение между реализациями Universo Platformo React и Universo Platformo Godot, выявляя архитектурные паттерны, лучшие практики и ключевые различия, чтобы обеспечить концептуальное соответствие версии Godot при использовании нативных возможностей движка Godot.

### Ключевые выводы

1. **Структура пакетов**: React использует 35 пакетов; планы Godot нуждаются в расширении для соответствия полному набору функций
2. **Общие утилиты**: React имеет хорошо установленные пакеты утилит, которые Godot должен воспроизвести
3. **Система экспорта**: Паттерн минипакетов React для экспортеров требует адаптации для Godot
4. **Аутентификация**: React использует Passport.js; Godot нужна эквивалентная реализация паттерна стратегий
5. **Система UPDL**: React имеет зрелую реализацию UPDL; Godot требуется всеобъемлющее планирование
6. **Система шаблонов**: React имеет пакеты шаблонов (quiz, mmoomm), которые Godot должен принять

## Сравнение архитектурных паттернов

### 1. Управление монорепозиторием

| Аспект | Реализация React | Реализация Godot | Статус |
|--------|-----------------|------------------|---------|
| **Менеджер пакетов** | PNPM с workspaces | Нет менеджера пакетов (система аддонов Godot) | ✅ Адаптировано |
| **Конфигурация Workspace** | pnpm-workspace.yaml | project.godot (регистрация аддонов) | ✅ Адаптировано |
| **Каталог зависимостей** | функция catalog в pnpm | DependencyCatalog.gd (запланировано) | 📋 Запланировано |
| **Шаблоны пакетов** | TEMPLATE-README.md | package-template/base/ (запланировано) | 📋 Запланировано |
| **Версионирование** | Семантическое версионирование в package.json | Поле version в plugin.cfg | ✅ Адаптировано |

**Ключевой инсайт**: Функция каталога PNPM в React для централизованного управления зависимостями превосходна. Godot должен реализовать аналогичную концепцию через `DependencyCatalog.gd` для отслеживания версий аддонов.

### 6. Система публикации с экспортерами

#### React: Паттерн минипакетов

Пакет publish в React использует "минипакеты" для экспортеров, специфичных для технологий:

```
packages/publish-frt/base/
└── exporters/
    ├── arjs/           # Минипакет экспортера AR.js
    ├── playcanvas/     # Минипакет экспортера PlayCanvas
    ├── babylonjs/      # Минипакет экспортера Babylon.js
    ├── threejs/        # Минипакет экспортера Three.js
    └── aframe/         # Минипакет экспортера A-Frame
```

Каждый минипакет реализует:
- `validate()` - Проверка требований экспорта
- `generate()` - Генерация файлов экспорта
- `package()` - Упаковка в дистрибутив
- `deploy()` - Развертывание на платформе (опционально)

**Адаптация Godot** (из spec.md FR-106 до FR-112):
```
packages/publish-frt/base/
└── exporters/
    ├── web-html5/      # Экспорт Godot в HTML5
    ├── desktop-native/ # Экспорт для десктопа
    └── mobile-android/ # Экспорт для Android
```

**Ключевое отличие**: Экспортеры Godot используют нативную систему экспорта Godot, а не кастомную генерацию кода.

**Статус**: ✅ Хорошо спланировано в spec.md (FR-106 до FR-112)

### 7. UPDL (Universal Platform Description Language)

#### Реализация UPDL в React

Пакет UPDL в React включает:
- JSON схему для описания сцен
- Парсер для UPDL JSON
- Валидатор для соответствия схеме
- Трансформер для UPDL ↔ React компоненты
- Сериализатор для экспорта в UPDL

**Структура схемы UPDL в React**:
```json
{
  "version": "1.0",
  "scene": {
    "name": "SceneName",
    "entities": [
      {
        "id": "entity_001",
        "name": "EntityName",
        "transform": {
          "position": [0, 0, 0],
          "rotation": [0, 0, 0],
          "scale": [1, 1, 1]
        },
        "components": [
          {
            "type": "Mesh",
            "properties": {...}
          }
        ]
      }
    ]
  }
}
```

**Адаптация UPDL для Godot** (из spec.md FR-113 до FR-119):

Godot должен использовать идентичную схему UPDL JSON, но трансформировать в/из сцен Godot (.tscn):

```
packages/updl/base/
├── parser/      # Парсер UPDL JSON
├── validator/   # Валидатор схемы
├── transformer/ # Трансформер UPDL ↔ сцены Godot
└── serializer/  # Сериализатор UPDL
```

**Статус**: ✅ Запланировано в spec.md (FR-113 до FR-119) с детальной архитектурой

### 2. Различие между Projects и Spaces ⚠️

**Реализация React**: 
- packages/projects-frt/srv - Управление проектами высокого уровня
- packages/spaces-frt/srv - Визуальное редактирование на основе холстов

**Статус Godot**: Упомянуты только spaces, projects не определены четко

**Рекомендация**: Прояснить различие:
- **Projects**: Контейнеры верхнего уровня для организации нескольких spaces

**Реализация React**: функция catalog в pnpm в pnpm-workspace.yaml
- Единый источник истины для версий
- Централизованное управление зависимостями
- Простое обновление версий

**Статус Godot**: Упомянуто в spec, но нуждается в деталях реализации

**Рекомендация**: Реализовать DependencyCatalog.gd (уже в spec.md, просто нужен акцент)

### 4. Система пакетов шаблонов 🔄

**Реализация React**:
- template-quiz: Шаблон викторины с потоком вопросов/ответов
- template-mmoomm: Специфичные шаблоны MMOOMM

**Статус Godot**: Упомянуто в spec (FR-088, FR-089), но минимальная детализация

- Создать template-quiz/base со сценами Godot

- Архитектура на основе комнат

- Авторитетный сервер

## Недостатки реализации React, которых следует избегать

### 1. Устаревший код Flowise ⚠️

**Проблема React**: Все еще содержит устаревшие пакеты Flowise, не полностью рефакторенные

**Решение Godot**: Начать с чистого листа, без багажа устаревшего кода ✅

### 2. Неполная папка docs/ ⚠️

**Проблема React**: Папка docs/ в основном репозитории (должна быть отдельной)

**Решение Godot**: Нет папки docs/ в основном репозитории (запланирован отдельный репозиторий) ✅

### 3. Несколько пакетов UI шаблонов ⚠️

**Проблема React**: Существуют и flowise-template-mui, и universo-template-mui

**Решение Godot**: Единый пакет universo-template-godot ✅

### 4. Непоследовательное именование пакетов ⚠️

**Проблема React**: Некоторым пакетам не хватает четкого суффикса -frt/-srv

**Решение Godot**: Строгое соблюдение соглашения об именовании ✅
