```
packages/{feature}-{type}/base/
├── plugin.cfg           # Метаданные аддона
├── plugin.gd            # Точка входа, extends EditorPlugin
```

- Зарегистрирован в `project.godot` в разделе `[autoload]` или `[plugins]`
- Зависимости объявлены в секции [dependencies] plugin.cfg
- Порядок загрузки контролируется конфигурацией проекта

### 2.5 SOLID принципы в GDScript ✅

**Источник лучшей практики**: GDQuest, документация лучших практик Godot

**Применение в проекте** (Конституция строки 106-115):

1. **Единственная ответственность**: Каждый пакет сосредоточен на одной функции
2. **Открыт/Закрыт**: Паттерн `base/` позволяет расширение без модификации
3. **Подстановка Лисков**: Будущие альтернативные реализации могут заменить base
4. **Разделение интерфейсов**: Четкие API пакетов, никаких раздутых интерфейсов
5. **Инверсия зависимостей**: Зависимость от абстракций (DatabaseManager, не Supabase напрямую)

**Пример: Абстракция базы данных** (Конституция строки 82-90)
```gdscript
# Хорошо: Зависимость от абстракции
DatabaseManager.execute_query(sql)

# Плохо: Зависимость от конкретной реализации
SupabaseClient.execute_query(sql)
```

**Валидация**: ✅ ПРОЙДЕНО - SOLID принципы задокументированы и применяются в архитектуре
