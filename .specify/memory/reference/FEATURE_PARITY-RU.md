## Ключевые архитектурные различия

### Адаптации React → Godot

**Управление пакетами**:
- React: PNPM workspaces с package.json
- Godot: Нативная система аддонов с plugin.cfg
- **Почему**: В Godot нет эквивалента npm, используется интегрированная система плагинов

**Frontend фреймворк**:
- React: JSX компоненты, виртуальный DOM
- Godot: Дерево сцен, нативные Control ноды
- **Почему**: Система сцен Godot больше подходит для игр/3D

**Backend фреймворк**:
- React: Архитектура middleware Express.js
- Godot: HTTPServer с обработчиками запросов
- **Почему**: Godot 4.3+ имеет нативный HTTP сервер

**Управление состоянием**:
- React: Redux (однонаправленный поток данных)
- Godot: Сигналы + autoload синглтоны
- **Почему**: Сигналы более идиоматичны для Godot/разработки игр

**Система типов**:
- React: TypeScript с .d.ts файлами
- Godot: Подсказки типов GDScript (нативные)
- **Почему**: Не требуется отдельный шаг компиляции

### Преимущества, специфичные для Godot

1. **Нативная система экспорта**: Экспорт на 10+ платформ из единой кодовой базы
2. **Производительность**: Выполнение нативного кода против JavaScript
3. **3D/Игровые функции**: Встроенная физика, анимация, частицы, шейдеры
4. **Опыт разработки**: Визуальный редактор, интегрированный отладчик, без шага сборки
5. **Сеть**: Нативный высокоуровневый API мультиплеера (ENet/WebSocket)

## Процесс мониторинга

1. **Еженедельная проверка**: Проверяйте репозиторий React каждый понедельник на наличие новых функций/изменений
2. **Создание Issue**: Создавайте отслеживающий issue в репозитории Godot для новых функций React
3. **Оценка приоритета**: Оценивайте релевантность и приоритет для реализации в Godot
4. **Спецификация**: Создавайте детальную спецификацию с использованием workflow `/speckit.specify`
5. **Реализация**: Следуйте стандартному workflow (спецификация → план → задачи → реализация)
6. **Документация**: Обновляйте этот файл при завершении реализации функции
