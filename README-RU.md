# Universo Platformo Godot

**Реализация Universo Platformo / Universo MMOOMM / Universo Kiberplano на основе Godot Engine и GDScript**

## Обзор

Universo Platformo Godot — это полнофункциональная реализация концепции Universo Platformo с использованием [Godot Engine](https://godotengine.org/) и GDScript. Этот проект предоставляет модульную, расширяемую платформу для создания приложений метавселенной, многопользовательских приложений и совместных цифровых пространств.

Эта реализация следует архитектурным паттернам, установленным в [Universo Platformo React](https://github.com/teknokomo/universo-platformo-react), но адаптированным для экосистемы Godot, используя GDScript как для фронтенда, так и для бэкенда.

## Ключевые возможности

- **Полнофункциональный GDScript**: Компоненты клиента и сервера написаны на GDScript
- **Модульная архитектура**: Структура на основе пакетов с четким разделением ответственности
- **Готовность к многопользовательскому режиму**: Встроенная поддержка сетевого взаимодействия и совместной работы в реальном времени
- **Интеграция с базой данных**: Поддержка Supabase с возможностью расширения для других баз данных
- **Расширяемый дизайн**: Базовые реализации позволяют использовать различные технологические стеки
- **Двуязычная документация**: Полная документация на английском и русском языках

## Организация пакетов

> **⚠️ ОБЯЗАТЕЛЬНАЯ АРХИТЕКТУРА**: ВСЯ функциональность (кроме общих файлов запуска/сборки) ДОЛЖНА быть реализована как пакеты в директории `packages/`. Эта модульная структура не подлежит обсуждению и готовит к будущему извлечению пакетов в отдельные репозитории.

Каждая функция в Universo Platformo организована в пакеты с компонентами фронтенда (`-frt`) и сервера (`-srv`):

### Соглашение об именовании пакетов
- `{feature}-frt/` - Реализация фронтенда/клиентской части
- `{feature}-srv/` - Реализация бэкенда/серверной части
- `{name}/` - Общие пакеты (типы, утилиты, ресурсы), используемые в нескольких функциях

### Базовая реализация
Каждый пакет содержит директорию `base/` для основной реализации. Эта структура позволяет создавать альтернативные реализации в будущем, сохраняя обратную совместимость.

Пример структуры для функции Кластеров:
```
packages/clusters-frt/base/
├── scenes/              # UI-сцены для кластеров
├── scripts/             # Логика клиентской части
├── plugin.cfg           # Конфигурация аддона Godot
└── plugin.gd            # Точка входа плагина

packages/clusters-srv/base/
├── scripts/             # Логика серверной части
├── api/                 # Конечные точки REST API
├── plugin.cfg           # Конфигурация аддона Godot
└── plugin.gd            # Точка входа плагина

packages/universo-types/base/
├── scripts/             # Общие модели данных и типы
├── plugin.cfg           # Конфигурация аддона Godot
└── plugin.gd            # Точка входа плагина
```

### Зачем нужны пакеты?
- **Модульность**: Каждый пакет разрабатывается и тестируется независимо
- **Будущая миграция**: Пакеты будут извлечены в отдельные репозитории по мере созревания проекта
- **Масштабируемость команды**: Несколько команд могут работать над разными пакетами параллельно
- **Четкие границы**: Структура пакетов обеспечивает разделение ответственности
- **Переиспользуемость**: Общие пакеты избегают дублирования кода

## Основные функции

### Система кластеров
Управляет инфраструктурой и организацией ресурсов через три основные сущности:
- **Кластеры**: Организационные единицы верхнего уровня
- **Домены**: Логические группировки внутри кластеров
- **Ресурсы**: Отдельные активы и компоненты

### Система метавселенных
Обрабатывает создание и управление виртуальными мирами:
- **Метавселенные**: Контейнеры виртуальных сред
- **Секции**: Подразделения внутри метавселенных
- **Сущности**: Объекты и акторы в метавселенной

### Пространства и холсты
Расширенные функции для совместной работы:
- **Пространства**: Общие рабочие области для команд
- **Холсты**: Интерфейсы визуального программирования
- **Узлы**: Реализация графа LangChain
- **UPDL-узлы**: Пользовательские узлы языка определения платформы Universo

### Система Уников
Управление уникальными ресурсами с расширенной иерархией сущностей

## Технологический стек

### Основные технологии
- **Движок**: Godot 4.x (последняя стабильная версия)
- **Язык**: GDScript
- **Сетевое взаимодействие**: Высокоуровневый API многопользовательского режима Godot
- **HTTP-сервер**: Пользовательская реализация REST API на GDScript

### База данных и бэкенд
- **Основная база данных**: Supabase
- **Аутентификация**: Пользовательская система аутентификации (реализация на GDScript)
- **Архитектура API**: RESTful конечные точки с использованием HTTP-сервера GDScript

### Будущие расширения
- Поддержка дополнительных баз данных (PostgreSQL, MongoDB и т.д.)
- Расширенные методы аутентификации
- Расширенные возможности API

## Начало работы

### Предварительные требования
- Godot Engine 4.x (последняя стабильная версия)
- Git для контроля версий
- Учетная запись Supabase (для функциональности базы данных)

### Установка

1. Клонируйте репозиторий:
```bash
git clone https://github.com/teknokomo/universo-platformo-godot.git
cd universo-platformo-godot
```

2. Откройте проект в Godot:
```bash
godot --editor project.godot
```

3. Настройте переменные окружения:
   - Скопируйте `.env.example` в `.env`
   - Добавьте свои учетные данные Supabase
   - Настройте другие необходимые параметры

4. Включите необходимые аддоны:
   - Откройте Настройки проекта → Плагины
   - Включите все необходимые аддоны Universo Platformo

### Запуск приложения

**Режим клиента:**
```bash
godot --path . scenes/main.tscn
```

**Режим сервера (без графики):**
```bash
godot --headless --path . scenes/server.tscn
```

**Режим разработки:**
Откройте проект в редакторе Godot и нажмите F5 для запуска

## Рабочий процесс разработки

### Создание новых функций

1. Создайте спецификацию с помощью команды `/speckit.specify`
2. Создайте Issue в GitHub, следуя `.github/instructions/github-issues.md`
3. Примените соответствующие метки согласно `.github/instructions/github-labels.md`
4. Создайте ветку функции и реализуйте
5. Создайте Pull Request, следуя `.github/instructions/github-pr.md`

### Разработка пакетов

При создании нового пакета:

1. Создайте директории пакета:
```bash
mkdir -p packages/{feature}-frt/base
mkdir -p packages/{feature}-srv/base
```

2. Добавьте `plugin.cfg` в каждую базовую директорию пакета
3. Реализуйте сцены и скрипты фронтенда в `-frt/base/`
4. Реализуйте логику бэкенда в `-srv/base/`
5. Задокументируйте пакет в собственных файлах README

### Стандарты документации

Вся документация должна следовать двуязычному стандарту:
1. Сначала создайте документацию на английском языке (например, `README.md`)
2. Создайте идентичную версию на русском языке (например, `README-RU.md`)
3. Убедитесь, что обе версии имеют одинаковую структуру и количество строк
4. Следуйте рекомендациям в `.github/instructions/i18n-docs.md`

## Принципы архитектуры

### Что мы берем из версии на React
- Структура монорепозитория с организацией на основе пакетов
- Разделение фронтенда/бэкенда внутри функций
- Папки базовой реализации для будущей расширяемости
- Supabase как основная база данных
- Подход к двуязычной документации

### Адаптации для Godot
- Система аддонов/плагинов вместо npm-пакетов
- GDScript для клиента и сервера
- Сцены Godot для UI-компонентов
- Встроенная сетевая поддержка Godot для многопользовательского режима
- Пользовательский HTTP-сервер для REST API

### Что мы не включаем
- Папку документации (`docs/`) - будет в отдельном репозитории
- Папки правил для AI-агентов - создаются пользователем по мере необходимости
- Устаревший код из других реализаций
- Несущественные файлы разработки
